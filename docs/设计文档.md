# 设计与口径说明

## 1. 目标

用 Olist 公开数据（2016-09 至 2018-08，约 9.9 万订单）回答四个问题：

- 客户价值：谁值得投入，复购情况如何
- 履约效率：从下单到送达的转化与流失
- 销售结构：类目、卖家、地域对销售额的贡献
- 物流时效：准时率，以及延误和评分的关系

## 2. 数据与质量

| 表 | 行数 | 质量情况 |
|---|---|---|
| customers | 99,441 | 无缺失 |
| geolocation | 1,000,163 | 同一邮编大量重复坐标 |
| order_items | 112,650 | 无缺失，383 条免运费 |

原始字段全部是文本，日期需要 `STR_TO_DATE` 转换。

## 3. 分层

| 层 | 表 | 内容 |
|---|---|---|
| ODS | 9 张原始表 | 由 CSV 直接导入 |
| DWD | dwd_orders / items / customers / sellers / products / geo / order_payment / reviews | 类型转换、去重、缺失处理、订单级聚合 |
| DWS | dws_order_wide | 订单 × 商品粒度，9 表关联，含距离与时效派生字段 |
| ADS | 无独立表 | 各 notebook 直接出结果 |

`dws_order_wide` 的派生字段：

- `distance_km`：客户与卖家邮编平均坐标的球面距离
- `delivered_days`：下单到签收
- `promise_days`：下单到承诺送达
- `slack_days`：承诺送达减实际送达，正数表示提前

## 4. 关键口径

**客户标识**：`customer_id` 是订单级匿名 ID，一个订单一个，不能用来算复购；真实客户用 `customer_unique_id`。用错的话频次恒为 1，复购率会算成 0。

**支付金额**：一单可能有多笔支付或分期，宽表关联前先按订单聚合，否则订单级金额会在每个商品行上重复累加。

**物流时效**：只用 `order_status = 'delivered'` 的订单，其余状态没有送达时间，直接参与计算会污染分母。

**RFM 的 F 维度**：97% 客户只有一单，频次几乎恒为 1，方差极低，因此放弃 F，只用 R + M 做四分位分层。

**流失**：`order_status` 属于 canceled 或 unavailable 视为流失，整体流失率 1.24%。

## 5. 分析结论

- 履约漏斗：支付转化 98.45%，送达率 97.02%，取消与不可用共 1,234 单。
- 流失归因：代金券订单流失率 3.62%，信用卡 1.15%，代金券是信用卡的 3 倍。
- 客户分层：93,358 名客户，97% 只买一次；核心高价值人群占 25.3%，贡献 42% 收入。
- 类目集中度：74 个类目里前 18 个贡献 80% 销售额。
- 增长结构：2018 年 GMV 739 万，新客首单占 96.7%-97.7%，复购不到 4%。
- 时效：已送达订单平均 12.6 天送达、承诺 23.7 天，平均提前 11.2 天，准时率 91.9%。
- 延误与评分：延迟 7 天以上的订单平均 1.74 分、差评率 78.2%；提前 7 天以上的平均 4.32 分、差评率 8.9%。

## 6. 遗留问题

- 单机 MySQL，未建索引，大表关联较慢。
- 承诺「收紧 N 天」的影响是基于历史分布的模拟，没有真实实验验证。
- 延误与评分只做了分档对比，没有控制品类、价格等混杂因素，不能直接当因果结论。
- 类目翻译表只覆盖 71 个类目。
